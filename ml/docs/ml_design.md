# ML 设计文档

## 目标

ML 模块负责把学生状态、资源库、知识图谱和大模型生成能力组合起来，形成“诊断-画像-推荐-规划-生成-反馈-再规划”的学习闭环。

## 输入数据

| 数据 | 字段 | 用途 |
| --- | --- | --- |
| 学生诊断 | 知识点掌握度、目标、偏好 | 初始化学习画像 |
| 历史画像 | 上一轮 mastery 状态 | 跨会话延续学生状态 |
| 行为日志 | 得分、完成率、停留时长、点赞/不喜欢 | 更新掌握度、投入度、稳定性和遗忘风险 |
| 资源库 | 知识点、难度、形式、时长、质量分、内容文本 | 推荐召回、排序和 RAG 证据检索 |
| 知识图谱 | 知识点、先修关系、重要性 | 生成学习路径 |

## 核心算法

1. 学习画像  
   诊断分数作为初值，可融合上一轮画像状态，再融合行为日志。行为信号由得分、完成状态、停留时长和反馈组成，并输出学习速度、投入度、稳定性、偏好置信度和遗忘风险。

2. 推荐排序  
   当前采用可解释加权模型：

   `score = 0.42 * 薄弱点匹配 + 0.24 * 难度匹配 + 0.14 * 形式偏好 + 0.14 * 资源质量 + 0.06 * 时长适配`

3. 多样性重排  
   对重复知识点和重复资源形式做轻量惩罚，避免 Top-K 推荐过于单一。

4. 学习路径规划  
   按“知识缺口 * 重要性”排序，并递归补齐未掌握的先修知识点。

5. RAG 内容生成  
   先把课程资源内容切片，再使用 BM25 风格检索召回与目标知识点相关的证据。配置 `DASHSCOPE_API_KEY` 后调用 Qwen-Max 生成 JSON 学习卡；未配置或调用失败时使用模板 fallback，保证离线演示稳定。

6. 生成质量检查  
   检查学习卡是否覆盖目标知识点，是否包含练习、答案、复习提示、错因分析和 RAG 证据，并输出可解释质量分。

## 多智能体闭环

系统返回 `agent_traces`，用于展示每个 Agent 的执行过程。

| Agent | 职责 |
| --- | --- |
| 诊断 Agent | 分析测评答案，输出知识点掌握度和薄弱点 |
| 画像 Agent | 融合诊断、行为日志和偏好，生成学生画像 |
| 推荐 Agent | 对资源进行可解释排序 |
| 规划 Agent | 基于知识图谱生成学习路径 |
| 生成与评估 Agent | 检索课程资源，生成学习卡并做质量检查 |

## API

| 接口 | 用途 |
| --- | --- |
| `POST /diagnose` | 输入测评答案，输出掌握度 |
| `POST /recommend` | 一次性输出画像、推荐、路径、学习卡和 Agent trace |
| `POST /path` | 输出学习路径和知识图谱 |
| `POST /generate` | 输出 RAG 学习卡 |
| `POST /feedback` | 输入学习反馈，输出反馈前后画像和路径变化 |

## 离线评估

运行：

```powershell
python ml/scripts/evaluate.py
```

当前支持：

- `Recall@K`：学生正反馈资源是否被召回。
- `NDCG@K`：正反馈资源是否排在更靠前的位置。
- 路径先修合理性：学习路径中先修知识是否出现在后续知识之前。
- 生成质量：学习卡质量检查分数。
- 推荐多样性：推荐资源形式覆盖和难度跨度。
- 掌握度提升示例：展示学习反馈进入系统后画像掌握度的变化。

## 后续升级

1. 数据达到几千条交互后，把规则权重替换为 LR、XGBoost 或 LightGBM 排序模型。
2. 资源文本足够丰富后，用文本向量做双塔召回，排序层继续融合画像特征。
3. 题目作答数据足够多后，引入知识追踪模型，例如 DKT 或 SAKT。
4. 大模型侧加入正式 RAG，先检索课程资源，再生成讲解和练习，降低幻觉。
5. 对生成内容加入安全校验：知识点覆盖、难度一致性、答案可验证性。
